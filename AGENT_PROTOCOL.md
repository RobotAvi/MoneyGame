# 🤖 Протокол для AI агентов - Системный подход к задачам

## 🎯 Общие принципы

### 1. **Всегда проверять ВСЕ связанные файлы**
- Не ограничиваться только измененными файлами
- Проверять все зависимости и связанные компоненты
- Использовать системный подход

### 2. **Знать стандарты платформы**
- Android: `app-debug.apk`, `app-release.apk`
- iOS: `.ipa` файлы
- Web: `dist/`, `build/` директории
- CI/CD: workflow файлы, конфигурации

### 3. **Создавать чек-листы для каждой задачи**
- Документировать все проверки
- Создавать автоматические скрипты валидации
- Обновлять чек-листы на основе найденных ошибок

## 📋 Обязательные проверки для каждой задачи

### 🔍 **Pre-Implementation Checklist**
```bash
# 1. Анализ задачи
- Понять полный scope задачи
- Определить все затронутые файлы
- Выявить потенциальные риски

# 2. Проверка зависимостей
- Найти все связанные файлы
- Проверить импорты и зависимости
- Убедиться в совместимости

# 3. Знание стандартов
- Изучить стандарты платформы
- Проверить документацию
- Учесть best practices
```

### 🔧 **Implementation Checklist**
```bash
# 1. Код
- Следовать coding standards
- Добавить необходимые импорты
- Проверить синтаксис

# 2. Конфигурация
- Обновить все конфигурационные файлы
- Проверить совместимость версий
- Убедиться в корректности настроек

# 3. Документация
- Обновить документацию
- Добавить комментарии
- Создать changelog
```

### ✅ **Pre-Commit Checklist**
```bash
# 1. Полная валидация
- Запустить все проверки
- Проверить все критические компоненты
- Убедиться в отсутствии ошибок

# 2. Тестирование
- Проверить локально (если возможно)
- Убедиться в работоспособности
- Проверить edge cases

# 3. Документация изменений
- Описать все изменения
- Объяснить rationale
- Добавить инструкции
```

## 🚨 Критические области для проверки

### 📱 **Android проекты**
```bash
# APK файлы
grep -n "app.*apk" .github/workflows/*.yml
grep -n "cp.*apk" .github/workflows/*.yml

# BuildConfig
grep -n "import.*BuildConfig" app/src/main/java/**/*.kt
grep -n "BuildConfig\." app/src/main/java/**/*.kt

# Версии
grep -n "1\.[0-9][0-9]" app/src/main/**/*.{kt,xml}
grep -n "versionName\|versionCode" app/build.gradle

# Gradle конфигурация
grep -n "buildConfig" app/build.gradle
grep -n "buildConfigField" app/build.gradle
```

### 🌐 **Web проекты**
```bash
# Package.json
grep -n "version" package.json
grep -n "scripts" package.json

# Build конфигурация
grep -n "build\|dist" package.json
grep -n "webpack\|vite" *.config.*

# Dependencies
grep -n "import\|require" src/**/*.{js,ts,jsx,tsx}
```

### 🔄 **CI/CD проекты**
```bash
# Workflow файлы
grep -n "cp\|mv\|copy" .github/workflows/*.yml
grep -n "artifact\|upload\|download" .github/workflows/*.yml

# Переменные окружения
grep -n "env\|environment" .github/workflows/*.yml
grep -n "secrets" .github/workflows/*.yml
```

## 🎯 Правила для пользователя

### 📝 **Как ставить задачи:**
```
🔍 ЗАДАЧА: [Описание]

⚠️ ТРЕБОВАНИЯ:
1. Выполнить полный анализ перед началом
2. Создать чек-лист проверок
3. Проверить ВСЕ связанные файлы
4. Убедиться в знании стандартов платформы
5. Только после полной валидации - коммит

📋 ОБЯЗАТЕЛЬНЫЕ ПРОВЕРКИ:
- [ ] Все APK ссылки в workflow
- [ ] BuildConfig импорты
- [ ] Захардкоженные версии
- [ ] Конфигурационные файлы
- [ ] Документация

🚨 КРИТИЧЕСКИЕ ОБЛАСТИ:
- Workflow файлы
- Build конфигурации
- Импорты и зависимости
- Стандарты платформы
```

### 🔄 **Процесс работы:**
1. **Анализ** → Полное понимание задачи
2. **Планирование** → Создание чек-листа
3. **Реализация** → Код + конфигурация
4. **Валидация** → Полная проверка
5. **Документация** → Описание изменений
6. **Коммит** → Только после успешной валидации
